# Component documentation template

Every component page in Storybook or Markdown should answer these questions.

## Purpose

What user need does this component serve?

## Use and avoid

- Use when:
- Avoid when:

## Anatomy

Describe the semantic elements, labels, content regions, and actions.

## API

List typed props, defaults, events/callbacks, slots, and controlled state.

## Variants and density

Document visual variants, `comfortable`, `compact`, and responsive changes.

## State matrix

Document applicable default, hover, focus, pressed, selected, disabled,
loading, error, success, empty, offline, syncing, conflict, and destructive
states.

## Accessibility

Document semantic HTML, accessible name, keyboard behavior, focus behavior,
status announcements, contrast, reduced motion, and error association.

## Content

Document label, helper, error, empty, and action copy. Use Indonesian-first
examples and mention localization constraints.

## Tokens and code

List semantic tokens consumed by the component and link to its Storybook story,
test, and pilot consumer.
